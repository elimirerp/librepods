# Modern NBA-MMS configuration evidence

Static audit of retained iOS 26 nearbyd/locationd and A3122 9A348 case NERF/ROSE. No phone, radio, account, build or app changes. Address references below are original virtual addresses. New raw slices and synthetic checks are retained in `work/uwb-protocol-agent/modern-nb-*` under the containing workspace.

## Result

**One complete source-grounded US configure-only candidate is recovered below.** Every numeric value comes from an actual native default, initialized constant, or legitimate native random-selection row. It has not been generated by a running iPhone or tested on the case. MMS gap is documented as the native raw controller quantity; its precise chip/time conversion is still unresolved. This candidate establishes a BLE configuration proposal, not Samsung NB compatibility or a working ranging session.

A configure-only operation is structurally separate from `070E` start, and does not require the *phone* to have a NB radio simply to write the BLE command. It **does configure the case's NB-capable Rose controller**, including NB and NB SAR power tables. No instruction-verified NB-disable/MMS-only setting was found in this `070D` path. BLE-disconnect cleanup for a configured NB session has not been established by the audited slices; the previous successful legacy configure-only cleanup does not prove this for modern NB.

## Case execution: configure is separate from start

1. Generic precision dispatcher requires owner pairing and HCI-encrypted connection. `070D` further requires initialized precision flag4 and capability bit1 at `0x241F0..2420C`. It is not a pairing/enrollment command.
2. `0x24210..2433E` parses the body and calls `0x25FE0`.
3. `0x25FE0..26016` copies19 bytes into `0x20011028`, then writes **1** to `0x2000FAD3` (NB mode). This function itself only stages RAM.
4. `0x241C0..1C4` posts event **0x1D**. Later ranging configuration handler `0x25AD6` calls `0x20198` with that staged body.
5. `0x20198` requires controller state8, rejects passthrough mode, extracts country, selects packet type and validates NB band/channel. It copies19 bytes into controller state `0x2000FD54`, forces NB configuration flag at state`+0x78` to1, then calls `0x1C994(args,9)` (`0x2024E..284`).
6. `0x1C994` builds and transmits a real Rose set-configuration command: UWB I/O, low-power RX and UWB power configuration, followed by NB power and NB SAR tables when NBflag1 (`0x1CAAC..1CB22`). Final controller transport is `0x1C448`, called at `0x1CBC6`. This is controller configuration, not merely successful GATT serialization.
7. `070E` is independent: stores16-byte IRK at `0x26024..2604C` and posts event **0x1F** (`0x2439E..3A6`). NB start lower handler `0x2050C` requires configuration-complete flag, retains IRK, changes state, and schedules the acquisition timer. No `070E` was executed by this audit.

Consequently: configuration can precede start; configuration still needs the **case's** NB controller. These instructions alone do not establish that configuration causes no calibration/receiver hardware work or RF activity, nor that host NB radio capability is unnecessary for a working ranging session.

## Exact completion

`0x23F84` reads NB mode; mode1 chooses **0x070F** at `0x23FC4..FCA`. The indication builder `0x23DBC` dispatch table routes070F to `0x23E94`, stores status as one **LE32**, sets body length **4**, and sends through `0x3C6D4`.

Thus successful completion frame is **`01 0F 07 00 00 00 00`**, total7 bytes. Nonzero LE32 is failure; status8 occurs in the actual controller state guards. Immediate authorization/schema failures may instead produce generic `0700` ACK/error. `070F` success confirms configuration completion; it does not confirm start, compatible phone waveform, distance or bearing.

Synthetic execution of unchanged firmware verifies070F status0/status8, exact four-byte copy, 19-byte staging, NB mode selection, and both mixed-MMS values. Evidence: `verify-modern-nb-config.py`, `modern-nb-synthetic-checks.json`. Logging, assertion handler and final controller transport are explicit harness boundaries; the synthetic body contains made-up NB/SAR selectors and **is not a live candidate**.

## Can NB be disabled while retaining MMS?

**No verified control in the audited 070D branch.** Concrete contrary evidence:

- bit4 `mms_mode` chooses UWB packet **0x0704** when0 and **0x0807** when1 (`0x201EA..2020C`); both paths continue through NB band validation and NB configuration.
- both force state`+0x78=1`, NB packet index1, controller configuration mode9, and NB power/SAR settings.
- neither a zero channel mask nor invalid band is a proven escape. Invalid band returns error1; masks are used by NB acquisition, not shown as an MMS-only session switch.
- the time-dithering/preamble-randomization flags are separate session options. Disabling them does not remove NB configuration.

The ROSE schema exposes separate `nb_tx_ant_mask`, `nb_rx_ant_mask`, `nb_pkt_type`, `nb_bch`, `nb_slot_sz_250us`, `mms_pkt_type`, `mms_psr`, `mms_gap`, `mms_seq_idx`, `mms_bch`, `mms_slot_sz_250us`, `mms_nfragments` and `irk`. Separate fields are not evidence of a supported BLE MMS-only mode. No route from070D to a mode that omits NB initialization was established.

## Cleanup limit and remaining work

Common Rose deinitialization is real: `0x248F0` calls controller deinit `0x1FED0`; `0x24C90` and multiple state-machine failure paths lead into deinitialization. **The incoming BLE disconnect event → configured NB state → deinit path was not recovered here**, so disconnect-only cleanup should not be advertised as verified modern-NB behavior. Explicit existing native stop/deinit handling should be decoded before a modern live trial.

## Native US regulatory proof

The authenticated virtual call `0x10033AB04` has discriminator `DAA7`. Retained fixup entry `0x1009D4800` resolves that slot to `0x1003829E0`, which adjusts the base and branches to `0x1003826C8`. That getter obtains regulatory settings with `0x10031BDDC`; it packs UWB byte into bits0..7, UNII3 country into bits8..15 and UNII3 SAR into bits16..23, then sets availability bit24 (`0x10038282C..840`). Defaults overrides named `UNII3RegulatoryGroup` and `UNII3SARGroup` exist, but the candidate uses the normal US table without overrides.

The US NB entry is built at `0x10045FF34..FFA0`. Registerx24 was set to `sp+0x6542` at `0x10045FE30..34`. The stores construct two triples **[0,1,1]** and **[1,1,1]**. Vector constructor `0x10045F4CC` consumes exact three-byte rows. The country map is installed at `0x100A2A798` (`0x100469A40..5C`); `0x10047EF18` obtains it; settings setter `0x10031B4F4..5D8` selects bandkey0 and retains its country/SAR selectors. Snapshot `0x10031BF4C..58` copies those values; getter packs them. Therefore the ordinary BLE updater's low nibbles are **1 and1**, while the updater leaves both high nibbles0. US UWB country0 comes from its independent table, not the NB groups.

Evidence: `modern-nb-us-country-entry{,-prefix}.asm`, `modern-nb-country-vector.asm`, `modern-nb-country-map-install.asm`, `modern-nb-country-table-lookup.asm`, `modern-nb-regulatory-snapshot.asm`, `modern-nb-regulatory-packed-getter{,-core}.asm`.
